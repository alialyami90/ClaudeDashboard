# 002 — Customizable Quick Launch deck

Quick Launch remains a native WPF widget with its existing icon-button style. Replace six fixed settings rows with a selected-button editor and variable-length local list. Preserve existing order, labels, targets and glyphs; distinguish a missing collection (defaults) from an intentionally empty collection. Missing action metadata is inferred from old URL/app targets.

The user requested easily assigned buttons comparable to other deck boards. [Elgato's system actions](https://help.elgato.com/hc/en-us/articles/360028234471-Elgato-Stream-Deck-System-Actions-Hotkey-Open-Website-Multimedia) informed the app/website/hotkey/media categories and selected-button editing. This implementation also exposes file/folder actions, existing dashboard controls, presets and a Start menu shortcut picker. Plugins, multi-action sequences, custom uploaded artwork and nested folders are outside this change.

The editor keeps a deep-copied draft until the existing Settings save transaction succeeds. Cancel discards it; failed saves retain it. Button counts are not fixed. The widget pages at six buttons, or three at minimum height, keeping touch targets usable without dashboard scrolling. The editor lives in `src/widgets/DeckEditor.cs`; action validation, app discovery and launch behavior live in `src/integrations/DeckActions.cs`; `DeckHotkeys.cs` owns Windows input integration.

Start menu enumeration runs once on demand in a worker task and avoids reparse-point recursion. It lists `.lnk` files from user/common Programs folders, not every registered Store app; Browse and registered URI schemes cover other assignments. Executables and shortcut files use Windows shell launch, with a distinct arguments field rather than parsing a command string. The existing limited Launcher remains available to other widgets. A missing unchanged target is retained and can report its failure at execution, so an unplugged drive cannot block theme changes.

Keyboard shortcuts use an event-based foreground-window hook, avoiding background polling. [SetWinEventHook](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-setwineventhook) retains the last external window; its process identity is checked before restoration. Input is sent only after focus is verified and physical modifier keys are released. [SendInput](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-sendinput) is subject to Windows integrity-level restrictions. It does not guarantee delivery to elevated apps or exclusive fullscreen games. No hooks capture typed text, and window identities are not persisted. Secure-attention sequences are rejected.

Confirmation is configurable and mandatory for arguments, common script/installer file types, Delete and Alt+F4. Arbitrary app-defined destructive hotkeys cannot be inferred; their user-assigned confirmation setting remains available. Runtime failures appear in the dashboard status. No action executes while configuring or validating settings.
